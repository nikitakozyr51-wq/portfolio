# Полный перенос desire.design из Framer

Цель: сохранить весь опубликованный сайт, его сетку, типографику, контент,
адаптивность и поведение; подготовить отдельно редактируемый документ `.pen`;
разместить проверенную версию на независимом хостинге. Coffee Owl — один из
десяти кейсов, а не граница работ.

## Что уже исследовано

- Получены HTML всех 28 адресов из sitemap.
- Все 28 страниц открыты с выполнением JavaScript в Chromium на ширинах 1440 и
  390 px. Сохранены 56 полноэкранных эталонов, видимый текст и размеры элементов.
- Исходные HTML находятся в `html/`, снимки — в `screenshots/`, список страниц,
  ссылок и ресурсов — в `inventory.json`. Файлы `*-1440.json` и `*-390.json`
  содержат измерения оригинала; `local-*` относятся к экспериментальному зеркалу.
- Главная использует Inter Tight Variable Regular. Зафиксированы переходы
  адаптивной вёрстки на 810 и 1200 px. У главной на 1440 px: внешние поля 20 px,
  верхнее поле основного блока 200 px, сетка верхнего блока из четырёх колонок
  по 335 px с интервалом 20 px. На 390 px: внешние поля 10 px, верхнее поле
  120 px, две колонки верхнего блока по 175 px с интервалом 20 px.
- На мобильной главной карточки чередуют ширину около 370 и 243.3 px.
  Это часть исходного дизайна; нельзя заменять её универсальной сеткой одинаковых карточек.
- Некоторым маршрутам сервер отдаёт почти пустой HTML. Например, Midnight Club
  наполняется после выполнения JavaScript. Это полноценная страница, а не
  отсутствующий кейс. Проверка только HTTP 200 или исходного HTML недостаточна.
- В видеокейсах найдены 16 отдельных iframe Kinescope. В Fast Bill также есть
  MP4 на CDN Framer; ряд карточек использует GIF как poster элемента video.
- Установлен официальный `@pen.dev/cli` версии 0.3.12 в `/workspace/tools/pen`.
  Проверены `pen version`, `pen status`, `pen interactive --help`. Попытка
  запуска интерактивного режима завершилась сообщением Authentication required.

## Что на самом деле можно экспортировать

### 1. Сохранение опубликованного кода — основной кандидат для точности

Сохраняются серверный HTML, исходный встроенный CSS, опубликованные модули
JavaScript и их зависимости, шрифты, изображения и видео. URL ресурсов
переписываются на собственное хранилище. Публичный браузерный код можно
исследовать и сохранить; доступ к внутреннему редактору и серверным сервисам
Framer из публичной ссылки не появляется.

Плюс: исходные CSS и клиентская логика дают лучший исходный шанс сохранить
вёрстку и анимации без повторного проектирования. Минусы: код минифицирован,
неудобен для ручной поддержки, может обращаться к платформенным сервисам;
контент и CMS не превращаются автоматически в удобный редактор. Каждый
обнаруженный сервис требует проверки или замены. Это не официальный экспорт
редактируемого Framer-проекта.

Для проверки написан `mirror.py`. Экспериментальное зеркало находится в
`mirror/`. `mirror-manifest.json` содержит адреса, хеши и размеры ресурсов.
Оно нужно для проверки метода; до завершения приёмки это не готовый релиз.

Загрузчик должен учитывать динамические import() и отдельно различать реальные
импорты и названия файлов внутри уже собранного bundle. Обычный wget/HTTrack
может быть полезен для первичного архива, но сам по себе не подтверждает
сохранность страниц, которые строятся клиентским JavaScript.

### 2. Перенос в поддерживаемые компоненты — при необходимости

Используется, если опубликованный код не удаётся отделить от Framer либо
потребуется удобное редактирование кейсов и дальнейшее развитие. Исходные
CSS-правила, измерения, контент и ресурсы остаются эталоном. Замена компонентов
идёт постепенно, с проверкой после каждого изменения. Не менять одновременно
фреймворк, сетку, контент, изображения и анимации.

Технология выбирается после проверки зеркала: для самостоятельных статичных
страниц достаточно статического размещения; для поддерживаемых шаблонов
подойдёт Astro или React. Next.js нужен только при соответствующих требованиях.
Выбор Vercel сам по себе не требует Next.js.

### 3. Reverse proxy

Framer официально описывает reverse proxy, включая размещение перед ним
другого хостинга. Этот вариант сохраняет Framer источником контента и не решает
полный уход с платформы. Для поставленной цели он не выбран основным путём.

## Отдельный редактируемый файл Pencil / pen.dev

Pencil сейчас называется pen.dev. Официальный CLI умеет работать с `.pen`
без графического интерфейса. Установка возможна и уже выполнена; это не
встраивает холст редактора в интерфейс веб-версии Codex.

Официальный импорт веб-страниц в редактируемые слои существует. Документация
относит встроенный браузер и импорт к настольному приложению. Наличие описания
`browser` в справке CLI не доказывает его работоспособность в headless-режиме.
После авторизации нужно проверить именно эту операцию на одной странице.
Импортированные слои не сохраняют JavaScript-взаимодействия страницы.

Порядок:

1. Авторизовать установленный CLI через поддерживаемый механизм. В настройках
   облачной среды сохранено требование `PEN_CLI_KEY` для `api.pen.dev`; значение
   вводится только в защищённых настройках. Локальная сессия с компьютера сюда
   не перенесена. Отдельный сторонний AI-агент для импорта не обязателен, если
   доступные операции CLI выполняют его непосредственно.
2. Проверить импорт страницы и экспорт её изображения. Открытие, сохранение и
   повторное открытие `.pen` должны пройти в установленной версии приложения.
3. Если headless-импорт не поддерживается, использовать документированный
   настольный импорт или построение слоёв через проверенные операции CLI.
   Вариант выбирается по фактической проверке, без обещания несуществующего
   преобразования Framer → Pencil одной командой.
4. Собрать в файле разделы Foundations, Components, Desktop, Tablet, Mobile и
   Interaction notes. Включить все уникальные шаблоны и все десять кейсов;
   новости и старую главную сохранить отдельной группой.
5. В Foundations сохранить размеры сеток, отступы, цвета, реальные шрифты,
   размеры текста и правила адаптивности. В Components — навигацию, меню,
   переключатели вида, категории, карточки, подписи и блоки кейсов.
6. Текст должен оставаться текстом, блоки — слоями, повторяемые элементы —
   компонентами. Скриншот страницы на холсте не является редактируемым макетом.
   Видео обозначаются постером и ссылкой на исходник; движение описывается
   отдельно и проверяется в браузере.
7. Проверить макет по эталонам и передать `.pen` вместе со всеми связанными
   изображениями и сведениями о шрифтах.

Редактируемый макет — отдельный обязательный результат. Не пропускать его
ради прототипа в браузере. При этом не использовать повторный экспорт
Framer → макет → HTML как автоматическое доказательство точности: такой
круг может потерять поведение и адаптивные правила. Сайт проверяется по
исходному Framer, макет — по тем же эталонам.

## Как проверять «один в один»

- Один браузер, масштаб, viewport, DPR, загруженные шрифты и состояние страницы
  для обеих версий. Скриншоты делаются после загрузки и согласованного прохода
  по странице, который активирует lazy loading.
- Базовая матрица: все 28 маршрутов на 390 и 1440 px. Дополнительно: 360,
  768, 809, 810, 1199, 1200 и 1920 px на каждом уникальном шаблоне.
- Геометрия: координаты и размеры карточек, колонок, заголовков, медиа,
  навигации и футера; ширины колонок, gap, padding, переносы текста. Допуск
  до 1 CSS px для округления предлагается как технический порог, а не как
  разрешение менять композицию. Любое систематическое смещение исправляется.
- Изображения: наложение оригинала и копии, карта различий и ручной просмотр.
  Одного среднего процента совпадения недостаточно: большой белый фон может
  скрыть потерянную карточку или текст.
- Видео и GIF сравниваются при одинаковом кадре или отдельно от статичной
  геометрии. Временное исключение движущейся области из pixel diff должно быть
  перечислено; затем проверяются её размер, кадрирование и воспроизведение.
- Не скрывать несовпадения отключением анимаций только в одной версии.
  Для движения отдельно проверить длительности, задержки, hover, прокрутку,
  переходы и режим уменьшенной анимации.
- Функции: все ссылки, фильтры и режимы каталога; menu open/close, Escape,
  Back/Forward; прямое открытие вложенных URL; обычная перезагрузка страницы;
  проигрывание, пауза и полноэкранный режим видео.
- Ресурсы: все необходимые файлы локальны либо используют явно выбранный
  сервис. Тест с блокировкой Framer обязателен. HTTP 200 без загруженного
  изображения или работающего плеера не считается успехом.
- Проверить поведение на реальном мобильном устройстве и Safari отдельно.
  Эмуляция узкого экрана в Chromium этого не подтверждает.
- Контент: сверить порядок кейсов, тексты, подписи, credits, годы и внешние
  ссылки. В исходнике есть `mailto:hello@oblica.com`, подпись `015 works`
  при десяти проектах и шаблонные заголовки `My Framer Site`. Их нельзя
  молча заменить выдуманными данными; записать как отдельные решения.

## Размещение и дальнейшее редактирование

Vercel — кандидат, доступность которого нужно проверить из России на нужных
сетях. Проверка из этой облачной машины не подтверждает доступность у
посетителей в России. Если адрес или CDN недоступны, выбирается другой
хостинг, совместимый со статическим сайтом.

Для зеркала требуется правильно заданный публичный origin: некоторые
сгенерированные модули Framer используют абсолютные URL как базу функции URL().
Простая замена всех адресов на относительные ломает клиентские страницы.
Параметр `PORTFOLIO_MIRROR_ORIGIN` задаёт адрес назначения при сборке зеркала.
Перед публикацией исключить localhost из конечных файлов и проверить все
пути на тестовом домене. Правила clean URLs должны сохранять пути без `.html`.

В ходе проверки обнаружен ещё один обязательный компонент: опубликованные
бинарные файлы `.framercms` и запросы к ним с параметром `range`. Для зеркала
сохранены полные файлы и реализована выдача нужных диапазонов локальным
сервером. При переносе на Vercel нужен эквивалентный обработчик или заранее
подготовленные данные в другом формате. Простая загрузка каталога на статический
хостинг пока не воспроизводит этот контракт.

Адреса ресурсов внутри CMS переписываются после декодирования строк. Изменять
длину строк непосредственно в бинарном файле нельзя: это нарушит индексы.
Такая адаптация зависит от конкретной версии опубликованного bundle и должна
быть проверена заново при новом экспорте. Для изображений сохранены также
точные CDN-варианты с параметрами размера; исходник максимального разрешения
не всегда даёт ту же скорость загрузки и тот же результат декодирования.

Подтверждённые особенности оригинала: мобильное меню содержит oblica,
hello@oblica.com и изображения шаблона; у отдельных video в поле адреса
оказывается целый HTML-код iframe, который браузер пытается загрузить как URL.
Это видно в DOM оригинального сайта и в данных CMS. Исправлять это нужно в
новой версии по отдельному списку, сохраняя исходный проект Framer без изменений.

После размещения проверить canonical, sitemap, robots, title/description,
социальные превью, favicon, страницу 404 и редиректы. Только после проверки
переключать основной домен. Не выключать прежний сайт до приёмки.

Для будущих правок следует отдельно решить, достаточно ли редактирования
репозитория или нужен редактор контента. Публичный bundle Framer не заменяет
CMS. Рефакторинг в удобные шаблоны может идти после сохранения точного эталона.

## Повторяемые инструменты и экономия работы

- `audit.py` — инвентаризация опубликованных маршрутов.
- `browser_audit.py` — реальные браузерные снимки и измерения. HTTPS-запросы
  проходят штатный прокси и проверку сертификатов через urllib; проверка TLS
  не отключена. Этот адаптер потребовался из-за доверия Chromium к сертификату
  прокси. Ошибки служебного iframe редактора Framer отмечены в исходных логах
  и не выдаются за доказанные ошибки портфолио.
- `mirror.py` — экспериментальная загрузка опубликованного кода и ресурсов.
- `serve_mirror.py` — локальная раздача зеркала для внутренней проверки.
- `compare_mirror.py` — сравнение текста и геометрии с блокировкой Framer.
- `check_flows.py` — навигация, мобильное меню и проверки медиа.
- `/workspace/tools/pen/node_modules/@pen.dev/cli/SKILL.md` — установленный
  официальный навык pen-design. Инструкции не заменяют авторизацию и проверку
  результата в самом редакторе.

Сохранять эталоны, загрузки и решения; повторять только проверки, на которые
влияют изменения, затем выполнять итоговую матрицу. Не генерировать дизайн
заново по описанию при каждом исправлении. Для работы использовать существующий
checkout: облачная задача уже изолирована, отдельный git worktree не нужен.
